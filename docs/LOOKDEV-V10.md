# V10 · 報平安照片、萬噸土產與節拍料理

本輪依使用者確認的故事方向實作。部署結果與最後驗證在下方分開記錄。

## 已實作

- 開場不限時看莊與龍泡泡，簡短買飯後，收到管理員訊息，再由玩家控制場景相機拍照。實際擷取 WebGL 畫面，照片可放大與拖曳；一樓、二樓線索位置來自拍攝當下的投影，取景不足會提示重拍。
- 選餐不再是主線入口。選一樓先看萬噸息壤貨單，選二樓先調查機房；兩條前段會合到弭弗通訊及砲擊主線。這是調查順序與前段對話差異，不宣稱兩套獨立結局。
- 莊知情安排轉運、店到店土產、隨貨龍泡泡與她親辦的天災保單形成前後笑點。管理員訊息、照片理賠、天災工號、清庫存等加入主線或結尾輪播。載入有十五句短笑話；開場等待與砲擊反應另有輪播池。
- 新增可見的實體監視器、鏡頭、支架與線材。VCR 先靠近監視器，再進入錄影；賽希先呈現天才邏輯，龍泡泡再向觀眾解釋。
- 賽希接線遊戲：轉動三塊線路，左右接通後揭露 `0000`。`login.php` 與 PHP 寬鬆比較作為虛構終端演出元素；不是最新 CVE，也沒有真實外部登入或漏洞攻擊。
- 加熱改為三段節拍，每段四個提示，短按與長按混合，命中三個可過關。首次測試明示電網額定輸出失控，必敗且不記玩家評分。其後失敗保留成功段落，降速並放寬判定，輔助有上限。
- 固定池製作紫色像素料理。開場先有三處殘留，回放較早時乾淨，失敗後噴出並停留；最多 96 塊，共用幾何、材質與 instanceColor，沒有新增全螢幕馬賽克後製。
- 通訊請求用已選弭弗 A 肖像，深色介面與接通按鈕等待玩家。登入縮成帳號三塊、密碼兩塊大鍵，保留龍泡泡踩實體鍵盤、驗證與拉桿。
- 開場與對話有對應分鏡。拖曳後自動運鏡停止，只有明確按鈕才恢復；精細操作採穩定鏡位。對話框標出顯示全文、繼續、演出中與暫停，按下有輕量視覺回應。
- 店內新增海報、轉運貨箱，二樓新增收藏及外送杯；焦黑微波爐仍面向客人操作區。這輪沿用店殼與原有室內鏡位，沒有新增通用的建築剖切系統。

## 人物與載入問題

使用者回報初始進入時兩位主角都消失，尚未在該 iPhone 重現，不能把推測當根因。已修正可確認的問題：

- 模型下載／解析失敗不再悄悄繼續啟動劇情。主畫面顯示失敗與單獨重試，保留街景與同一 Renderer。
- 初始成功載入後明確開啟人物，避免瀏覽器恢復舊的未勾選表單狀態。角色網格不再依賴可能過時的蒙皮視錐邊界。
- 街景先可見，初始只預備人物材質；賽希在開場劇情開始時預載。回放未就緒則保留戰場，顯示小型下載／解析提示及重試。
- 已知下載總量才顯示百分比；壓縮回應的 Content-Length 不當作解壓後總量。沒有總量時顯示 MB。下載停滯四十秒可重試；進度持續則重設停滯計時。
- 原始兩份 GLB 未改，授權與來源保留。沒有宣稱已完成模型壓縮或 iPhone 穩定 30 FPS。

## 驗證

- `npm install`、正式 Repository base 的 `npm run build` 已執行。Vite 仍有主 chunk 超過 500 kB 的提醒。
- 狀態／故事 96、運鏡 63、道具 49、原始模型骨架 69、破壞 36、砲擊資源 25、著色器 15 項檢查通過。
- 桌面 Chromium／SwiftShader 的 30 項實際網頁整合檢查涵蓋兩種調查入口、拍攝與照片標記、接聽、五鍵登入、三十秒充能、99% 回放、接線、首次失控、輔助加熱、返回、終末彈、重播與橫式。結尾另外以真實時間持續觀察至少六十秒。正式 build 為 `index-PmsBhbHP.js`／`index-CwTAfxj0.css`，公開部署需與此版核對。
- 7 項首次模型 HTTP 503 故障測試確認：有主畫面重試，重試確實再次下載，兩位角色恢復，且仍只有一個 Renderer 與一組主線 UI；也模擬未勾選人物的表單恢復狀態。
- 節拍 UI 另有 6 項實際瀏覽器按下／放開事件測試，含三段短按與長按；不是只呼叫成功函式。
- 自動流程使用可檢查的劇情時鐘，不能當 FPS 基準。軟體 WebGL、390×844 視窗、合成輸入均不是 iPhone Safari 真機。

證據：`artifacts/v10-mission-check.json`、`v10-browser-results.json`、`v10-startup-results.json`、`v10-rhythm-ui.json`，以及各子系統的 V10 JSON。
