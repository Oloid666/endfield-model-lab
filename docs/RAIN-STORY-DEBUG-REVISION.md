# 洛西、晚餐誕生與快速測試修訂

日期：2026-11-06。沿用 Three.js 0.180.0、原角色模型、八題課堂與既有部署方式。此文件記錄本輪修改；發布版本以遊戲設定選單的版本及 GitHub commit 為準。

## 這次改了什麼

### 洛西收藏與少女自介

- 手辦沿用本地程序模型，維持 956 個三角形、單一網格、一次物件繪製，不增加模型或貼圖下載。
- 放大 1.8 倍至約 60 公分，移至二樓靠窗矮機櫃頂部。展示組直接附在真正的伺服器房群組，機櫃下降、摧毀與復原時一起移動／隱藏。
- 底座抬高，臉部避開窗框橫桿；告示放在旁邊。現有機房光源照明，沒有新增動態陰影。
- 「主嫌自介寫」先展示收藏環境，「少女可以……不能三四十歲」切手辦特寫，再接莊「幫我找一條罪名」。以語意 cue 選鏡頭，不受台詞序號改動影響。

### 紫色生物誕生

`src/meal-birth.js` 提供共用演出階段，微波爐、紫色生物與相機都讀取同一個可暫停的劇情時鐘：

| 時間 | 表現 |
| --- | --- |
| 0–1.5 秒 | 電網突波，電流持續灌入 |
| 1.5–3 秒 | 飯菜焦黑、電弧增加 |
| 3–4.8 秒 | 紫色黏團從便當內鼓起、膨脹 |
| 4.8–6.5 秒 | 門閂受壓彈開，黏團從門縫連續擠出 |
| 6.5–8 秒 | 落到延伸的加熱檯面，壓扁回彈；塞西稍微後退 |
| 8 秒後 | 拍生物與塞西，逐句等待玩家閱讀原因、莊的反應、龍泡泡送餐吐槽 |

- 不再由首輪失敗訊息提前說出「紫色生物」。誕生後才說「把晚餐電活了」。
- 完整對話讀完才回節奏加熱，長時間停留不會自行略過。首輪電網突波不計玩家操作失敗，後續失敗不重複生成生物。
- 一部分焦黑飯菜形成生物，便當盒與其餘食物保留；從誕生、廢墟到通關跟隨沿用同一個生物。
- 微波爐門是獨立轉軸群組，門框及把手按材質合批，保留即時變黑；沒有加入物理引擎。
- 減少動態模式保留相同先後關係，使用穩定鏡頭與較少彈跳。

### 妮姬木馬說明

對話先用「木馬會偷帳號密碼」交代風險，再解釋惡意程式混入正常更新的供應鏈攻擊。龍泡泡吐槽「別人偷帳號，妳偷電？」；塞西回答照說明借電，延續她不會駭客技術的設定。

平板及實體電腦另有 CDN 腳本遭竄改、憑證竊取（Credential theft）、C2 遠端控制通道等資訊。設備建立鏡頭與螢幕近景使用不同 beat，避免鏡頭還在遠處時就開始解說。保留拉毗先露臉、答應後 0.7 秒才遮眼、之後才開放供電按鈕的時序。

這些功能仍是本地劇情演出，不會連線或控制外部設備。沒有新增未核實的駭客姓名或漏洞編號。

## 七下解鎖與快速測試

點正面 711 招牌七次，維持直接進入完整房子的通關街角，另開放左下角「快速測試」。

- 主線章節：晚餐拍照、萬噸簽收、電網接通、三小時前、最後一擊。
- 重點演出：冰箱反轉、妮姬木馬、紫色生物誕生、洛西自介、卡洞後首次復原。
- 二樓與結尾：理賠、八題課堂、評分、通關街角。

切換時結束舊二樓轉場、釋放行走輸入、清除相機慣性並建立所需劇情與設備狀態。塞西尚未載入時先等待資產；重新開始後，已取消的載入跳轉不能回寫新畫面。二樓也可以打開快速測試返回街角。

解鎖只保留在本次頁面記憶體。章節／演出跳轉保留解鎖；重新開始或重新整理後清除。捷徑不生成尚未出生的紫色生物。測試流程沿用 `shortcut` 統計分類，不記成正常主線通關，也不解鎖正常章節紀錄。

沒有新增後端或服務端 API。`MissionMachine.restoreDebugPoint()` 及原有 `window.__rainy711` 下的 debug 查詢／跳轉是內部測試入口。

## 驗證

- 37 組 Node 檢查通過，包含原有 36 組及新增的誕生／分鏡／手辦檢查；語意分鏡在台詞重新編號後仍對應相同畫面。
- `npm run build` 成功，保留原有大於 500 kB 的 bundle 提示。沒有更新套件或調整部署設定。
- 新的 `scripts/story-revision-browser-check.py` 在實際 Chromium／SwiftShader 驗證：七次實際點招牌、直橫向手辦、誕生各階段、手動對話、竊密說明與延遲遮眼、二樓三種入口返回、首次復原、連續六次拆／復原，以及重開／重新整理清除捷徑。
- 另以 `CANCEL_ONLY=1` 驗證模型仍在載入時重新開始：舊跳轉取消、解鎖清除，暫停再解除也沒有殘留的載入暫停；二樓轉場被測試跳轉中斷後同樣不會回寫舊畫面。
- 六次建物切換後，量測到 renderer 計數維持 **264 個幾何、97 張貼圖、77 個 program**，沒有隨切換持續增長。這是同次軟體 WebGL 的資源穩定性檢查，不是 iPhone FPS 或效能提升證明。
- 原有完整 `scripts/vcr-browser-check.py` 通過：原主線、十次節奏背景恢復、發射鎖鏡、理賠、八題課堂、評分草稿、六次房屋切換、實際鍵盤走到馬路並返回，以及重新開始後隱藏操作。誕生驗收同步改為等待三句手動對話。
- 尚未執行 iPhone Safari 真機、真實 App 切換或發熱後效能測試；上述互動驗收使用本機正式建置，發布時另核對線上版本。
