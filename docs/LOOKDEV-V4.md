# 第四輪：雨夜材質、細節、走路與晚餐短劇

本輪依使用者最新指示，從場景預覽擴充為可以散步、選餐與觀看結局的互動短劇。舊文件中「故事與走路尚未加入」為前版狀態。

## 參考頁分析與實作

已透過正常 TLS 深讀 `https://rainy-711.shareyourhtml.com/` 的原始 HTML，分析其 HDR 多重取樣、不同尺度的玻璃水珠、重力滑動、水膜、長條光源、濕地材質、光源分層與招牌比例。未把參考頁截圖當作網站背景；模型與程序街景仍是本專案實際 Three.js 畫面。

### 人物細節與光影

- 修正原本後製 RenderTarget 沒有多重取樣的問題。依 RGBA16F 實際支援的樣本數，標準／細緻最高 4× MSAA、省電最高 2×，最後加 FXAA。
- 初始 DPR 上限 1.25，細緻上限 1.5。保留原 GLB，執行時紋理 anisotropy 8。
- 相機最小距離從 5.5m 改為 0.75m，增加跟隨人物位置的「近看」特寫。
- 降低濃霧，補冷色背巷燈、暖窗與後側月光。店外加入長條冷白螢光燈，雨棚保留暖光。
- 人物正面補光會跟隨行走位置。沒有以增加全場曝光取代人物補光。

### 濕地與玻璃

- 室外上表面直接取用共用平面反射，加入濕暗底色、水窪、低粗糙度與小幅水波。解決人行道高於車道反射平面、看起來乾燥的問題。
- 玻璃水珠依公尺計算，加入兩種靜止水珠、不同速度的下滑水珠、重力方向尾跡、少量折射與水膜模糊。
- 冰箱門保留較低濕度；玻璃海報集中在局部，不封住中央視線。
- 全部玻璃共用色彩與深度緩衝，利用深度避免覆蓋前方人物。沒有每片窗各重畫一次場景。

人行道共用車道反射，並非每塊地磚都有獨立反射相機。抬高的地面會有近似誤差；濕地擾動與柔化可降低可見程度。

### 實景配置

- 雙片感應自動門，接近時開啟，離開後延遲關門。活動門片不參與靜態合批。
- 後排冰箱、低雙面貨架、右側收銀台；咖啡機、微波爐與後場服務台分區，付款、裝袋與熱食空間分開。
- 後通道約 0.93m，員工通道約 0.88m。
- 重做 7-ELEVEN 向量標誌、長型燈箱與雙面側招牌；三色條帶採不同高度。
- 水塔改為有金屬環、圓頂與遮屏的雙塔；補室外機、格柵與管線、腳踏車、迎賓地毯、分類垃圾桶、椅背與扶手、紅綠燈、停車牌、鄰房窗框及陽台。

## 散步與角色表演

「散步」開啟搖桿或鍵盤方向輸入。範圍限制在有相同地坪高度的店內與騎樓，不包含車道。人物有加減速、轉向、雙腿步態、反向擺臂，並避開貨架、櫃台與非入口玻璃。

走路使用雙腿 IK；停下重新固定雙腳。龍泡泡會跟隨，並有短手腳步態與表情。58 個原有衣服、頭髮與袖口關節加入輕微風動；這是骨架動畫，沒有布料物理。

三份晚餐使用不同立體道具，跟隨人物手部與龍泡泡。手機只在相關動作時亮起。沒有精準抓握、咀嚼或完整開放世界。

## 短劇與 UI

- 98 個主線／尾聲資料節點，每筆包含 id、speaker、text、mood、gesture、next，選項另有 choices。
- 三種晚餐、三段分支台詞、三個命名結局，外加可選的思念管理員尾聲及兩種回應。
- 16 組結尾閒聊，每組 2–4 句；組間安靜 8–14 秒，不連續重複，不打斷主線。
- 五類熱點各三組反應。同一物件有冷卻，回應不疊加；拖曳、多指、長按與取消不觸發短點。
- 點擊台詞繼續、可自動、略過本段、收起暫停與重新選餐。選項永遠等待，不會倒數自選。
- 少量字幕只在段落轉換出現，不逐句遮畫面。故事不是全螢幕結算卡，結束後場景繼續運作。

所有故事與動作使用唯一場景時鐘。頁面進入背景時停止更新，沒有另外開一組劇本計時器。

十年加班、思念管理員及台詞為原創二創設定，介面「關於」明確標示。問候選項不會傳送真實訊息。

## 可重現檢查

- `node scripts/story-check.mjs`：411 項通過，涵蓋九條晚餐／尾聲路徑、選項等待、略過、重播、閒聊輪替、冷卻與暫停。結果：`artifacts/story-check.json`。
- `node scripts/actor-check.mjs`：22 項通過。讀取真實 GLB 骨架與幾何，僅在記憶體中移除測試不需要的圖片材質。核對 569 個關節、58 個次級動畫關節、實際姿勢改變、腳部目標、入口與障礙、道具差異及轉向重設。結果：`artifacts/actor-check.json`。
- 上述骨架檢查的誤差：待機最大 2.50mm、走路最大 13.81mm、停步後最大 1.40mm。這些是姿勢約束結果，不能當作抓握精準度或 GPU 效能證據。
- `npm run build` 通過。單一 JS chunk 仍超過 500 kB，沒有隱藏 Vite 警告。

`python scripts/browser-v4.py` 在桌面 Chromium／SwiftShader 通過 41 項檢查，包括實際 HDR 4× MSAA＋FXAA、畫質切換後深度可用、自動門開關、模型移動、三條晚餐流程與道具、選項等待、拖曳防誤觸、重播及 WebGL Context Lost／Restored。結果在 `artifacts/v4-browser-results.json`。

結尾持續觀察 60.13 秒，共 29 幀，確實出現閒聊並返回安靜狀態。軟體 WebGL 約 0.48 FPS，未達 30 FPS。這是 CPU 軟體渲染環境，不能推算 iPhone GPU 表現。

另以 `scripts/visual-v4.py` 通過 19 項最終截圖、操作列與三段 MSAA 畫質檢查；調整視窗尺寸後等待 ResizeObserver，再實際渲染，避免把暫停渲染時的清空畫布當成場景截圖。主要畫面為 `artifacts/v4-portrait.png`、`v4-detail.png`、`v4-dinner-choice.png`、`v4-meal-A.png`、`v4-meal-B.png`、`v4-meal-C.png`、`v4-coda.png`、`v4-landscape.png`、`v4-desktop.png`。全部是本機實際 WebGL 畫面，結果在 `artifacts/v4-visual-results.json`。

開發時發現並修正濕地反射的讀寫回授、反射局部／世界座標混用，以及 Raycaster 仍命中隱藏道具的問題。反射擷取期間改用安全的空白紋理，擷取完成後恢復反射；切換視角、調整尺寸、恢復 Context 及切換畫質時強制重新擷取，避免沿用舊鏡頭的反射。最終三段畫質與畫面檢查的 WebGL 錯誤均為零。

iPhone Safari 真機測試仍待進行，不能宣稱已達穩定 30 FPS。公開網址的 HTTP 資源核對與部署結果會另行記錄；本機截圖不會當成真機或公開網址的瀏覽器截圖。
